# 性能工程

## 目标指标

每个发布版本必须记录 CPU/GPU 吞吐、端到端延迟、编译时间、峰值显存、L1/L2/L3 权重命中率、allocator 碎片、kernel cache 命中率、通信有效带宽、通信计算重叠率、专家等待和 DataLoader 利用率。

## 测量协议

基准在固定硬件、驱动、存储设备、互连、nightly toolchain、环境变量、线程数和数据种子下执行。分层模型额外固定模型包布局、量化格式、batch、上下文、并发和冷热缓存状态。每项至少完成预热、稳定采样和冷启动三组测量，报告中位数、分位数和离散度。禁止以单次最快结果作为门槛依据。

## 回归阈值

默认阻断条件：吞吐下降超过 5%，p95 延迟上升超过 10%，峰值显存上升超过 8%，编译时间上升超过 15%，或通信有效带宽下降超过 10%。涉及正确性、确定性或安全的变更即使性能改善也不能跳过功能门槛。

## 优化顺序

先检查图融合、layout、memory planner 和 kernel 选择，再检查线程和 transport 参数。所有优化必须保留可复现配置、基准输入摘要和前后遥测，避免只对单一设备过拟合。
