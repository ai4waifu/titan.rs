# 安全规范

## Unsafe 审计

每个 `unsafe` 块必须写明前置条件、别名规则、对齐、生命周期和设备同步假设，并提供最小测试。审查者必须检查裸指针来源、整数溢出、slice 长度、Send/Sync 实现和 panic 路径。unsafe 不得跨越公共 API 边界泄漏未验证状态。

## GPU kernel 与动态库

kernel 二进制只从受信任缓存和配置的路径加载。加载前校验 ABI 版本、目标架构、文件 checksum 和签名；禁止把用户输入拼接为动态库路径或编译命令。JIT 编译使用参数数组和受限环境，超时后清理子进程和临时工件。

## 集群端点

控制面和数据面默认 mTLS、节点白名单和最小权限。endpoint、证书、token 不写入日志和遥测。所有管理 API 记录审计事件，危险操作需要显式权限和幂等 request id。

## Checkpoint

恢复前验证 manifest 签名、schema、文件 checksum、大小、shard 范围和 tensor 摘要。路径必须限制在配置的存储根目录内，拒绝绝对路径、目录穿越、符号链接逃逸和超大稀疏文件。

## 遥测与前端

遥测默认脱敏，不收集输入、参数原值和密钥；远端发送使用 TLS、批次鉴权和过期 token。Web UI 遵守服务端授权，浏览器只拿到聚合数据，下载和恢复操作需要审计。
