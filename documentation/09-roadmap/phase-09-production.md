# 阶段 09：生产化与发布

## 前置条件

- 前八阶段全部通过统一验收门槛。
- API、artifact、telemetry、kernel ABI 和控制面协议均有版本策略。
- 安全审计、性能基线和故障注入环境可自动执行。

## 代码交付物

- 可复现构建、SBOM、签名、工件校验和发布清单。
- schema migration、兼容读取、版本探测和回滚工具。
- 生产配置验证、资源配额、超时、限流、审计和密钥接入。
- soak、故障注入、升级、降级和 disaster recovery 自动化。
- 支持矩阵内的 Native CUDA/ROCm 部署包、领域模型包与独立 Web UI 产物。

## API 交付物

- 稳定公共 facade、模型接口、工具 CLI 和只读观测 API。
- 版本、capability、health、readiness 和 build info 接口。
- 破坏性变更的迁移路径、弃用周期和机器可读错误。

## 测试交付物

- 全 feature、全 target、依赖最小版本和上一兼容版本测试。
- 数值、性能、安全、fuzz corpus 和多小时 soak test。
- 节点丢失、磁盘满、网络分区、设备复位、缓存损坏和 schema 迁移测试。
- 安装、升级、回滚、checkpoint 恢复、领域模型和 Web UI 兼容测试。

## 性能交付物

- 代表模型的单机和多机吞吐、延迟、显存、scaling 和恢复时间基线。
- 发布候选相对稳定版本的自动回归报告。
- 至少一次长时间运行的内存增长、句柄增长和 telemetry 配额报告。

## 文档交付物

- 支持矩阵、部署、升级、回滚、安全、故障处理和发布说明。
- crate、宏、CLI、Web API、artifact、model package 和 schema 的版本化参考。

## 失败条件

- 构建无法复现或工件无法验证来源。
- 生产运行依赖未固定的外部工具、隐式全局状态或人工恢复步骤。
- 版本升级导致已提交 checkpoint、`.tune`、模型包或遥测不可读且无迁移器。
- soak test 出现持续内存/句柄增长、死锁或数据不一致。

## 完成验收

发布候选通过构建、测试、基准、安全、soak、升级与回滚全链路；在受支持集群完成训练、分层推理、故障恢复、诊断和 Web UI 观测，并能回退到上一稳定版本。

## 解锁条件

达到可发布状态。后续版本从性能、算子、模型、领域和后端工作包进入同一门槛体系，不绕过兼容性与恢复协议。
